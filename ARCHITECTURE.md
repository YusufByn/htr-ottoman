# Architecture

Structure du code et flux des données. Mis à jour à chaque étape terminée.
Dernière mise à jour : 2026-09-29.

## 1. Vue d'ensemble

```
data/raw/makhzan/  (zip + TSV, lecture seule)
   │
   ├──> analysis ───────────────────────────────> reports/  (inventaires, comparaisons)
   │
   └──> data.makhzan ──> data/interim/makhzan/  (images + ALTO par manuscrit, table des lignes)
                                          │
                        splits ──> splits/│  (train / val / test_interne, une ligne par page)
                                          │
  prepare : normalize + compilation (anciens polygones)
                                          v
                                   data/processed/  (jeux prêts pour kraken, par split)
                                          │
        train (configs/*.yml) ──> models/  (modèles affinés) + reports/training/, reports/figures/
                                          │
            predict + evaluate ──> reports/ + EXPERIMENTS.md  (CER ; baseline : reports/baseline/)
                                          │
  analysis.error_analysis (validation seulement) ──> reports/erreurs/  (catégories d'erreurs, confusions, pires lignes)
  lignes.parquet de F9 (test interne, SHA-256 vérifiés) ──> analysis.error_analysis --exploratoire-test-interne ──> reports/f13/ (F13, comptes et catégories seulement, « exploratoire, décision 39 »)
  lignes.parquet de F9 (test interne, SHA-256 vérifiés) ──> analysis.category_check ──> reports/f13/q1_conventions/lecture/ (F13, Q1, page de lecture, texte seulement)
  échantillon + jugements de Q1 + categories.csv (test interne exploratoire, validation F12) ──> analysis.category_check_results ──> reports/f13/q1_conventions/ (F13, Q1)
  test_interne.arrow + ALTO et images (Doc 3179, sans prédiction ni modèle) ──> analysis.doc3179 ──> reports/f13/q6_doc3179/ (F13, Q6, page de lecture à l'aveugle)
  lignes.parquet de F9 (SHA-256 vérifiés) + tableaux exploratoires (b4bdb1b) + jugements de Q6 ──> analysis.doc3179_results ──> reports/f13/q6_doc3179/ (F13, Q6)
                                          │
  final_eval (configs/f9_*.yml) : contrôles bloquants, predict + evaluate + compare
                                          v
                                   reports/comparaisons/  (différence de CER, bootstrap apparié)

  compare_variant (F12, validation seulement) : variante contre F8, bruit des seeds 42 à 44,
  bootstrap apparié par page, règle de la décision 42 ──> reports/comparaisons/<variante>_f8_finetune/val/
                                                    (sans variante : bruit seul ──> reports/bruit/f8_finetune/, reports/bruit/f8_lag15_seed42/)
  reports/training/*.csv ──> analysis.seed_curves ──> reports/bruit/f8_finetune/, reports/figures/f12_bruit_seeds.png
  reports/training/*.csv ──> analysis.same_curve  (contrôle de déterminisme : mêmes métriques époque par époque)
  best_*.safetensors + checkpoint_*.ckpt ──> analysis.same_tensors ──> reports/f14/tenseurs/ (F14 : époque du meilleur modèle)
  jeux compilés (vérité terrain) ──> analysis.ketos_char_count ──> reports/f13/q2_ketos_evaluate/ (F13, Q2)
  train.arrow + lignes.parquet sauvegardés ──> analysis.rare_chars ──> reports/f13/q7_caracteres/ (F13, Q7)
  train (vérité terrain, ALTO, images) ──> analysis.period_ink ──> reports/f13/q5_points/ (F13, Q5, page de lecture à l'aveugle)
  reports/{baseline,f8_finetune,f8_lag15_seed42}/val/lignes.parquet ──> analysis.period_errors ──> reports/f13/q5_points/validation_points.csv
  val.arrow + ALTO et images (Doc 2937) ──> analysis.red_ink ──> reports/f13/q3_encre_rouge/ (F13, Q3, page de lecture à l'aveugle)
  lignes.parquet sauvegardés (validation, test interne) + jugements ──> analysis.red_ink_errors ──> reports/f13/q3_encre_rouge/ (F13, Q3)
  lignes.parquet F8 (lag 5) (validation) + ALTO et images (Doc 2937) ──> analysis.final_ya ──> reports/f13/q4_ya_final/ (F13, Q4, page de lecture à l'aveugle)
  lignes.parquet sauvegardés (validation) + train + jugements ──> analysis.final_ya_errors ──> reports/f13/q4_ya_final/ (F13, Q4)
  train (configs lag 15 de F12, décision 43) ──> ketos_capped (ketos train + plafond d'époques) ──> models/

data/raw/akis/  (zip git LFS, lecture seule) ──> data.akis ──> data/interim/akis/  (lignes découpées, table des lignes)
                                                                   │
                                  analysis.akis_inventory ──> reports/akis_*.csv  (vérification F10 ; Akis écarté, décision 40)
```

Le pipeline part toujours de `data/raw/`, qui n'est jamais modifié. Chaque étape lit la sortie de la précédente et écrit dans son propre dossier.

## 2. Arborescence

```
htr-ottoman/
├── configs/              un fichier YAML par expérience (f8_finetune.yml, répétitions f8_finetune_seed43.yml et _seed44.yml ; F12 : f8_lag15_seed42/43/44.yml, variante f12_b_augment.yml, essais techniques essai_technique_plafond.yml et essai_technique_b_augment.yml) ou évaluation finale (f9_test_interne.yml)
├── data/                 hors git
│   ├── raw/              sources telles que téléchargées, en lecture seule (chmod a-w)
│   ├── interim/          zips décompressés, ALTO bruts, avant normalisation
│   └── processed/        makhzan/alto/ (ALTO normalisés), makhzan/<jeu>.arrow et <jeu>.lst
├── models/               modèle de départ (openiti_ottoman_print/) et modèles entraînés (hors git)
├── notebooks/            exploration visuelle uniquement, aucun code du pipeline n'en dépend
├── reports/              inventaires, métriques (versionné, CC BY-NC-SA ; source et exceptions : reports/LICENCE.md)
│   ├── baseline/         F7 : prédictions et CER du modèle de départ, un dossier par jeu (val/, test_interne/)
│   ├── f8_finetune/      prédictions et CER du modèle F8 : validation (val/, F8) et test interne (test_interne/, F9, avec run.json et ketos_test.txt)
│   ├── f8_finetune_seed<N>/  prédictions et CER des répétitions de F8 sur la validation (val/, F12, décision 42)
│   ├── comparaisons/     comparaisons appariées de deux modèles, <modèle>_<référence>/<jeu>/ (F12 : <variante>_f8_finetune/val/)
│   ├── erreurs/          analyse des erreurs de deux modèles, <modèle>_<référence>/val/ (F12, validation seulement)
│   ├── bruit/            F12 : bruit entre répétitions de F8 (f8_finetune/ : lag 5, CER par seed, écart et seuil S, diagnostic des courbes ; f8_lag15_seed42/ : lag 15, CER par seed, écart et seuil S)
│   ├── training/         métriques par époque de chaque entraînement retenu (<config>.csv)
│   └── figures/          graphiques générés par les modules d'analyse
├── scripts/              utilitaires (vérification d'environnement) et contrôles ponctuels (F14)
├── splits/               listes train/val/test figées, avec la seed (versionné)
├── src/htr_ottoman/      package Python du projet
│   ├── config.py         chemins du projet, définis une seule fois
│   ├── data/             download.py (MD5 ou SHA-256, idempotent), alto.py (lecture ALTO), makhzan.py, annotations.py, akis.py
│   ├── analysis/         inventaires et comparaisons descriptives
│   ├── base_model.py     modèle de départ : téléchargement, chargement kraken, codec (lu dans reports/codec_modele_depart.json)
│   ├── normalize.py      l'unique fonction de normalisation (NFD + règles documentées)
│   ├── splits.py         découpage par œuvre, fichiers de splits/ et contrôle d'étanchéité
│   ├── prepare.py        ALTO normalisés, compilation Arrow pour kraken, vérifications
│   ├── prepare_sans_gen2.py  F12, variante C : train de F8 sans les pages gen2, compilé à part
│   ├── publish.py        F14 : copie du modèle publié, drapeau « anciens polygones » corrigé dans l'en-tête (décision 45)
│   ├── predict.py        prédictions ligne par ligne (API kraken, BiDi)
│   ├── evaluate.py       CER micro global et ventilé, bootstrap par manuscrit
│   ├── compare.py        comparaison appariée de deux modèles (différence de CER, bootstrap apparié)
│   ├── compare_variant.py  F12 : variante contre F8 sur la validation (bruit, bootstrap par page, décision 42)
│   ├── final_eval.py     évaluation pré-enregistrée sur un jeu réservé, avec contrôles bloquants
│   ├── ketos_capped.py   lance `ketos train` avec l'arrêt anticipé et un plafond d'époques (F12, décision 43)
│   └── train.py          fine-tuning kraken piloté par une config de configs/
├── tests/                tests automatiques (pytest)
└── pyproject.toml, uv.lock, LICENSE (MIT, code), MODEL_CARD.md (carte du modèle publié), README.md, CLAUDE.md, DECISIONS.md, EXPERIMENTS.md, ARCHITECTURE.md, PROJECT.md, DATASETS.md
```

## 5. Configurations

Un fichier YAML par expérience d'entraînement dans `configs/`, lu par `train`. Deux sections : `ketos` (options globales, avant `train`) et `train` (options de `ketos train`). Les clés sont les noms longs des options de ketos sans les tirets (`lrate`, `batch-size`, `reorder`), les chemins sont relatifs à la racine. Le format natif de ketos (`--config`) n'est pas utilisé : il ignore une clé inconnue avec un simple avertissement. `train` ajoute lui-même la sortie, le journal TensorBoard et `-v`. Premier fichier : `configs/f8_finetune.yml` (décisions 33 à 35). Répétitions pour le bruit (F12, décision 42) : `configs/f8_finetune_seed43.yml` et `configs/f8_finetune_seed44.yml`, identiques à F8 à la seed près (vérifié par `train.check`). Variantes de F12 (décisions 42 et 43) : `configs/f12_b_augment.yml`, `configs/f12_a_lr3e-4.yml`, `configs/f12_c_sans_gen2.yml`, chacune `f8_lag15_seed42` avec une seule clé changée (vérifié par `tests/test_train.py`), et leurs essais techniques `configs/essai_technique_*.yml` (plafond 1).

Les évaluations finales ont aussi leur fichier, lu par `final_eval` : `configs/f9_test_interne.yml` fixe le jeu, le modèle et son SHA-256, la référence, l'empreinte de ses prédictions, les effectifs attendus et les dossiers de sortie (décisions 37 et 38). Il est committé avant la prédiction.

## 6. Conventions

- **Chemins** : toujours importés de `htr_ottoman.config`, jamais écrits en dur dans un module.
- **Données brutes** : `data/raw/` est en lecture seule (`chmod a-w`) ; aucun module n'y écrit.
- **Identifiants** : les fichiers MAKHZAN sont nommés `<DocID>_<DocPartID>.jpg` / `.xml` ; un Doc ID est un document eScriptorium, une œuvre est identifiée par `Title of Text` (décision 6).
- **Normalisation** : appliquée en un seul point, par `normalize`, à la vérité terrain et aux prédictions (décisions 5 et 8). Toute nouvelle règle : une fonction dans `RULES`, une docstring, un test, une décision. Les annotations de transcripteur ne sont pas normalisées mais filtrées en F4 (décision 15).
- **Valeurs multiples** dans les CSV de `reports/` : séparées par ` | `.
- **Seeds** : `SEED = 42` dans `splits.py`, écrite dans l'en-tête des fichiers de `splits/` ; les configs d'entraînement la reprendront. L'affectation aux jeux ne dépend d'aucun tirage.
- **kraken** : toujours lire la skill `.claude/skills/kraken/` avant de l'utiliser. Réglages de texte : `prepare.KRAKEN_TEXT_OPTIONS` ; découpe : anciens polygones ; prédictions via l'API Python ou `ketos test`, pas `kraken ocr` ; tout code qui lance kraken tourne dans un module avec `if __name__ == "__main__":` (processus parallèles).
- **Fichiers générés versionnés** (`splits/`, `reports/`) : jamais de date ni d'élément variable dans leur contenu, pour que la régénération soit vérifiable par comparaison. Seule exception : `run.json` et `ketos_test.txt` de `reports/f8_finetune/test_interne/`, journaux de la consultation unique du test interne (dates, durées, barre de progression de ketos). Ils ne sont jamais régénérés et ne sont pas relus par les tests.
- **Test interne clos** (décision 39) : aucune prédiction dessus depuis F9 ; `predict` la refuse. Ses tableaux se recalculent à partir des prédictions sauvegardées (`evaluate`, `compare`).
- **Lancement** : `uv run python -m htr_ottoman.<module>`.
- **Dépendances** (`pyproject.toml`) : kraken 7.1.1, pandas, tensorboard (journal des métriques d'entraînement, lu par `train`), matplotlib (courbes).
